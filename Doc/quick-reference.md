# 開発プロセス クイックリファレンス

> 📌 **常に手元に置いておきたい開発ルールの要点集**

---

## 🎯 基本原則（絶対に守る3つのこと）

1. **毎日動かす**: 1日の終わりには必ず動作する状態にする
2. **こまめに確認**: ブラウザで頻繁に動作確認する
3. **壊さない**: 既存機能が壊れていないか常にチェックする

---

## ✅ Definition of Done（完了の定義）

PBIが完了したと判断する基準：

- [ ] 受入基準がすべて満たされている
- [ ] **E2Eテストが成功している**（ブラウザで実際に操作して確認）
- [ ] 既存機能が壊れていない（リグレッションテスト実施）
- [ ] エラーハンドリングが実装されている
- [ ] コードが可読性・保守性を満たしている
- [ ] 主要ブラウザで動作確認済み
- [ ] セキュリティチェック完了

---

## 🔄 実装フロー（Outside-In）

### Phase 1: UI First（UIから着手）
```
1. HTMLマークアップ作成
2. CSS スタイリング
3. イベントハンドラー仮実装
→ ブラウザで画面表示確認 ✅
```

### Phase 2: Integration（統合・実動作）
```
4. APIクライアント実装/利用
5. データバインディング
6. ステート管理実装
→ ブラウザで実際のデータ表示確認 ✅
```

### Phase 3: Refinement（改善・エラー処理）
```
7. エラーハンドリング強化
8. エッジケース対応
9. リファクタリング
→ ブラウザで異常系確認 ✅
```

### Phase 4: Testing（テスト・ドキュメント）
```
10. E2Eテスト実施
11. リグレッションテスト実施
12. テスト結果記録
13. ドキュメント更新
→ DoDをすべて満たす ✅
```

---

## 📝 テスト実施ルール

### E2Eテスト
- **実際にブラウザで操作**してテストする
- テストシナリオに従って手順を実行
- 各ステップで期待結果を確認
- 問題があればその場で修正

### リグレッションテスト
- 毎日の開発終了時に実施
- [RG001: メインフロー煙テスト](./test-cases/regression/RG001_main_flow_smoke_test.md) を実行
- 所要時間: 約5分
- Passになるまで修正

---

## 🛠️ デイリールーチン

### 開発開始時（10分）
1. 今日のタスクを確認
2. 前日の成果を確認（動作する状態か？）
3. ブロッカーがないか確認

### 開発終了時（15分）
1. **必ず動作する状態にする**（最重要）
2. E2Eテストを実施
3. リグレッションテスト（RG001）を実施
4. コミット・プッシュ
5. 明日のタスクを確認

---

## 🐛 問題発生時のフロー

```
問題発生
  ↓
エラーメッセージを確認
  ↓
最後に動いていた状態を思い出す
  ↓
変更差分を確認（git diff）
  ↓
段階的にロールバックしてテスト
  ↓
原因特定 → 修正
  ↓
E2Eテストで確認
  ↓
リグレッションテストで確認
  ↓
完了
```

```javascript
// 定数: UPPER_SNAKE_CASE
```

### エラーハンドリング
```javascript
try {
  const response = await fetch(API_ENDPOINT, ...);
  if (!response.ok) {
    throw new Error(`API Error: ${response.status}`);
  }
```

## 🔍 デバッグ手順

1. **コンソールを確認** → エラーメッセージを読む
2. **console.logでデバッグ** → 値を確認
3. **DevToolsを活用** → Network/Application/Elementsタブ
4. **段階的に原因を特定** → 1つずつ変更を加える

## 💡 よくある質問

### Q: E2Eテストは毎回すべてのシナリオを実行する必要がある？
A: いいえ。通常はクイックテスト（主要フロー）を実施。詳細テストはPBI完了時やスプリント終了時に実施。

### Q: コードレビューは必須？
A: 単独開発の場合はセルフレビュー。チームの場合はペアレビュー推奨。

### Q: ドキュメントはいつ更新する？
A: PBI実装時にリアルタイムで更新。後回しにすると忘れる。

### Q: 問題が解決できない場合は？
A: ドキュメント確認 → Web検索 → チームに相談 → イシュー起票
