# RG001: メインフロー煙テスト（Smoke Test）

## テスト情報
- **テストケースID**: RG001
- **テストタイプ**: リグレッションテスト / 煙テスト
- **実施タイミング**: 毎日の開発終了時、すべてのPBI実装後
- **所要時間**: 約5分
- **優先度**: 最高
- **自動化**: 手動（将来的に自動化検討）

---

## 目的
アプリケーションの基本的な動作が壊れていないことを迅速に確認する

**煙テスト（Smoke Test）とは**:
最も重要な機能が動作することを確認する簡易テスト。詳細なテストの前に実施し、基本的な動作が確保されているかを素早くチェックする。

---

## 実施基準

### 実施が必須の場合
- [ ] 新しいPBIを実装した後
- [ ] 既存コードを変更した後
- [ ] 毎日の開発終了時
- [ ] mainブランチへのマージ前
- [ ] リリース前

### 実施をスキップできる場合
- CSSのみの変更（機能に影響なし）
- ドキュメントのみの変更

---

## 前提条件
- [ ] ブラウザが起動している
- [ ] アプリケーションが起動している
- [ ] 有効なAPIキーを用意している
- [ ] インターネット接続がある（API呼び出しのため）

## 問題発見時の対応

### Fail時のアクション
1. **問題箇所を特定**
   - どのステップで失敗したか記録
   - エラーメッセージをコピー
   - スクリーンショット取得

2. **問題を記録**
   - イシュー起票
   - 下記の「発見した問題」セクションに記入

3. **修正**
   - すぐに修正できる場合は修正
   - 複雑な場合はロールバックも検討

4. **再テスト**
   - 修正後、再度このテストを実施
   - Passになるまで繰り返す

## 備考

### テストのコツ
- **毎日同じ時間に実施**すると習慣化しやすい
- **タイマーで5分を計測**し、素早く実施する
- **問題があればすぐに対処**し、翌日に持ち越さない

### 拡張テストが必要な場合
以下の変更時は、このテストに加えて詳細なE2Eテストも実施する:
- API連携部分の変更
- 状態管理ロジックの変更
- セキュリティに関わる変更
- パフォーマンスに影響する変更
