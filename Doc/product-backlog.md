# プロダクトバックログ - 研修ナレーションスタジオ

## バージョン情報
- 最終更新日: 2025-12-06
- 対象プロダクト: 研修ナレーションスタジオ（シンプル版）
- プロダクトゴール: ブラウザだけで Gemini TTS を利用し、講師が原稿を入力して即時にナレーション音声を生成・ダウンロードできる個人向けツール

#### PBI-003: APIクライアント実装 【優先度: 最高】
**ストーリー**: 開発者として、Gemini TTS API との通信を抽象化したクライアントモジュールを実装したい

**受入基準**:
- [x] API クライアントクラス/モジュールが実装されている
- [x] 単一話者TTS生成機能が動作する
- [x] 複数話者（2名）TTS生成機能が動作する
- [x] エラーハンドリングが実装されている
- [x] Base64デコード処理が実装されている
- [x] レスポンスからWAV Blobを生成できる

**見積もり**: 8 SP

**技術メモ**:
- エンドポイント: `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-preview-tts:generateContent`
- 音声形式: 24kHz PCM 16-bit mono
- エラー型: 401 (認証), 429 (レート制限), 400 (リクエストエラー)

**進捗メモ (2025-11-24)**:
- `src/js/api-client.js` に `GeminiTtsClient` を追加し、単一/複数話者TTS、エラーハンドリング、Base64→WAV Blob 変換を実装
- `src/js/app.js` からクライアントをimportし、APIキー設定時にクライアントへ伝播
- 次は generate ボタンフローからクライアントを呼び出し、実際の音声生成を連携する

**進捗メモ (2025-11-25)**:
- Google AI SDK（`@google/generative-ai`）に移行し、`src/index.html` に import map を追加してブラウザだけで SDK を読み込める構成に変更
- SDK に合わせて `GeminiTtsClient` を全面改修（単一/複数話者 API の再実装、エラー整備）
- SDK が返す `audio/L16` PCM をブラウザで再生できるよう `convertPcm16ToWav` を実装し、WAV Blob へ変換
- `src/js/app.js` からの生成フローを SDK 版クライアントに接続し、生成〜再生 UI の差し替えを完了

## 技術的負債・リスク

### リスク項目
1. **localStorage 容量制限** (約5MB): 音声Blobをlocalstorageに保存できない
   - 対策: 音声はBlob URLのみ保持、セッション終了後は破棄

2. **API レート制限**: Gemini API のレート制限に抵触する可能性
   - 対策: リトライロジック実装、エラーハンドリング強化

3. **長文処理のタイムアウト**: 非同期処理の時間制限
   - 対策: セクション分割を細かくする、タイムアウト時間を適切に設定

4. **ブラウザ互換性**: Safari, Edge での動作確認
   - 対策: Polyfill導入、クロスブラウザテスト

5. **XSS脆弱性**: ユーザー入力の原稿にスクリプトが含まれる可能性
   - 対策: サニタイゼーション処理、CSP設定

6. **アプリケーションコードの肥大化**: `src/js/app.js` が単一ファイルで肥大し変更コストが高い
   - 対策: PBI-037 でモジュール分割と責務整理を実施

7. **Pro TTS サーバー実装の二重管理**: Node/Express 版と Python/Flask 版が並存し、設定が分散
   - 対策: PBI-038 で公式実装を一本化し、設定を共有化

8. **環境設定値のハードコード**: API ベース URL や料金係数がコード内に固定されている
   - 対策: PBI-039 で外部設定ファイル化とドキュメント整備を実施

9. **Google AI SDK バージョン不一致**: CDN 版と npm 版でバージョンが異なり、再現性に難
   - 対策: PBI-040 でバージョン統一と検証ログ整備を行う

10. **音声プリセット定義の重複**: HTML 内で Speaker A/B 用に同じ `option` 群を二重管理
    - 対策: PBI-041 で単一データソース化しレンダリング処理を共通化

11. **ローカルポート設定の不整合**: 起動スクリプトと Playwright 設定でポートが異なりテスト失敗につながる
    - 対策: PBI-042 でポート定義を共通化し、自動伝播の仕組みを導入
