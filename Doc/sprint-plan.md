## リスクと対応策

### 主要リスク

#### 1. API レート制限に抵触
**影響度**: 高
**対応策**:
- リトライロジックの実装
- エラーメッセージの明確化
- ユーザーへの待機案内

#### 2. ブラウザの localStorage 容量不足
**影響度**: 中
**対応策**:
- 音声データはBlob URLのみ保持（Base64保存しない）
- 履歴件数の制限（最新50件）
- 古い履歴の自動削除

#### 3. 長文処理のタイムアウト
**影響度**: 中
**対応策**:
- セクション分割の細分化
- タイムアウト時間の適切な設定
- ユーザーへのタイムアウト説明

#### 4. クロスブラウザ互換性問題
**影響度**: 中
**対応策**:
- 早期のクロスブラウザテスト
- Polyfillの導入
- 非対応ブラウザへの警告表示

#### 5. XSS脆弱性
**影響度**: 高
**対応策**:
- ユーザー入力のサニタイゼーション
- CSP (Content Security Policy) 設定
- セキュリティレビュー実施

2. **今日やること**: 着手予定のタスク
3. **ブロッカー**: 進捗を妨げている問題
4. **質問**: チームに確認したいこと

### 状況確認ポイント
- スプリントゴール達成に向けた進捗率
- 残りSPと残り日数のバランス
- ブロッカーの有無と解決策
- PBIの完了基準（DoD）達成状況

---

## スプリントレトロスペクティブ（振り返り）

### 振り返りフレームワーク（KPT法推奨）

#### Keep（良かったこと・継続すること）
- 例: API疎通が早期に完了し、リスクを低減できた

#### Problem（問題・課題）
- 例: セクション分割ロジックが複雑で見積もりを超過した

#### Try（次に試すこと）
- 例: 複雑なロジックは事前にスパイク（調査）タスクを設ける

---

## 付録: ストーリーポイント見積もり基準

### SPの目安（1人日 = 8時間と仮定）
- **1 SP**: 1〜2時間（非常に簡単なタスク）
- **2 SP**: 2〜4時間（簡単なタスク）
- **3 SP**: 4〜8時間（中程度のタスク、約1日）
- **5 SP**: 1〜2日（やや複雑なタスク）
- **8 SP**: 2〜3日（複雑なタスク）
- **13 SP**: 3〜5日（非常に複雑なタスク、分割検討）

### 見積もり会議（プランニングポーカー）
- チーム全員で相対見積もりを実施
- フィボナッチ数列（1, 2, 3, 5, 8, 13）を使用
- 意見が分かれた場合は議論して合意形成

## まとめ

このスプリント計画により、8週間（4スプリント）で**研修ナレーションスタジオ（シンプル版）**の開発を完了する見込みです。

### 開発完了時に実現される機能
✅ APIキー管理
✅ 原稿入力・編集
✅ 2名の話者設定
✅ Gemini TTS API連携
✅ 音声生成・再生・ダウンロード
✅ セクション分割・プレビュー
✅ 履歴管理
✅ レスポンシブデザイン
✅ ヘルプ・設定画面

各スプリント終了時にはスプリントレビューを実施し、ステークホルダーにデモを行うことで、継続的なフィードバックを得ながら開発を進めます。
